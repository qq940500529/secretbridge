# 稳定性与故障注入验收

[文档中心](../README.md) / 稳定性与故障注入验收

本验收面向 SecretBridge 开源版的个人本机、单用户运行规模。目标不是模拟企业集群负载，而是确认连接器、终端和本地配置在常见故障下能够及时结束、返回固定且脱敏的结果、释放自身资源，并允许用户继续工作。

## 验收分层

| 层级 | 用途 | 命令 |
|---|---|---|
| 快速验收 | 开发和 PR 回归，完整运行连接器故障合同、合成终端洪泛及本机真实 Shell | `python tools/acceptance/test_stability_acceptance.py --profile quick` |
| 重复长稳 | 重复饱和并发、取消、资源归还和后续成功请求，默认 20 轮；同一临时目录跨两次测试进程累计 4,000 次授权与运行，重开目录并检查备份恢复 | `python tools/acceptance/test_stability_acceptance.py --profile soak --iterations 20` |
| 真实数据库 | 在一次性 PostgreSQL/MySQL 容器中补充查询期间重启和恢复 | `python tools/acceptance/test_stability_acceptance.py --profile quick --with-databases` |

结果默认写入被 Git 忽略的 `dist/stability-acceptance.json`。报告只记录平台、架构、检查名称、命令、耗时、退出码、固定失败码和结果。同目录长稳还记录每 1,000 次后的授权/运行数量、目录文件字节数、Linux 驻留内存页数，以及备份字节数；不包含测试输出、目录、主机信息或凭据值。`--report` 可以指定其他位置。任一阶段失败或超时都会写入已完成阶段和固定失败码。

同目录测试用随机命名的独立临时目录，在第一个测试进程中分两阶段完成 2,000 次授权与运行，关闭并重新打开同一 SQLite 数据库，再由第二个测试进程复用该目录，分两阶段完成另 2,000 次。每阶段都核对历史、安全事件和保留输出；每个进程结束前备份、校验并在内存中恢复全部历史。脚本退出时只删除自己创建的临时目录。此项不等同于实际桌面常驻数周的观察。

仓库还包含每周及手工触发的 Ubuntu 长稳工作流 `.github/workflows/stability-soak.yml`。普通 PR 的 Rust 全量测试已经运行快速合同；定期工作流负责发现重复运行后才出现的许可、进程或状态残留。

## 故障矩阵

| 范围 | 注入方式 | 必须观察到的结果 |
|---|---|---|
| HTTP | 回环端口拒绝连接；响应声明长度后提前断开；慢请求超时与取消 | `connection_failed`、`response_read_failed`、`timed_out` 或 `cancelled`；不返回上游异常正文 |
| SSH | 监听端停止；已执行远程命令时关闭实际传输；显式取消与超时 | 固定连接或退出状态错误；传输关闭；无密码、私钥或上游调试内容 |
| SFTP | 传输中关闭 SSH 运输；慢写取消；远端写入、删除和原子替换失败 | 原目标保留；临时文件尽量删除；`cleanup_ok` 明确说明清理结果 |
| Git HTTPS | 重定向、认证失败、缺失仓库、慢请求取消以及服务中断 | `git_failed`、`timed_out` 或 `cancelled`；令牌及 Basic 编码形式均被过滤 |
| PostgreSQL/MySQL | 拒绝连接、错误认证、查询超时、显式取消、查询期间重启真实容器 | 固定连接/查询错误；清理结果明确；数据库恢复后新连接可成功 |
| 持久终端 | 2 MiB 输出洪泛、广播滞后、游标缺口、断开重连及长任务终止 | 其他会话仍可工作；缺口显式报告；只回放保留窗口；取消有界完成 |
| 并发任务 | 同时提交八个慢任务，饱和四个执行许可后全部取消 | 配置读写仍响应；运行和排队任务均结束；四个许可全部归还；后续请求成功 |
| 同目录历史增长 | 同一临时目录跨两次测试进程累计 4,000 次授权与运行，在中间和结束时重开并备份 | 历史、安全事件、输出可查询；备份可校验恢复；资源和数据库增长进入脱敏报告 |
| 本地写入 | 凭据临时目录不可创建；模板更新在凭据关联写入时失败 | 不留下秘密文件、部分模板更新、失效关联或成功状态 |

测试仅使用每次生成的本机服务、一次性目录和合成凭据，不连接业务系统。数据库模式仅操作脚本自己创建并在退出时删除的容器。

## 结果合同

连接器不会把操作系统或协议库的原始异常直接发送给 Web 或 MCP。故障通过固定错误代码表达；运行状态、错误代码和退出码由同一次目录事务提交。适用时，结果还包含 `cleanup_ok`：

- `true`：已确认本次操作拥有的连接、部分文件或临时材料清理完成；
- `false`：清理尝试已经在有界时间内结束，但无法确认远端或本地临时材料全部删除；
- 不存在：该连接器没有需要向用户声明的额外清理步骤。

取消只承诺停止 SecretBridge 拥有的本地执行和传输。已经被远端服务接受的 Git 推送、SSH 命令或其他业务副作用不承诺回滚。

## 个人使用规模基线

- 凭据任务最多同时占用四个执行许可；额外任务等待许可而不阻塞配置目录；
- 终端为独立系统进程，输出回放窗口保持 64 KiB；落后读取者收到缺口或背压通知；
- 单次任务、响应和数据库结果继续使用各连接器既有大小与超时上限；
- 取消、超时或服务停止后，验收等待所有运行登记清空并验证许可恢复到四个；
- 并发取消重复轮数限制为 1—100；同目录历史测试固定为 4,000 次授权与运行，避免无界压力测试。

## 真实数据库重启

`tools/acceptance/test_database_connectors.sh` 创建带合成密码和临时 TLS 证书的 PostgreSQL 与 MySQL 容器。必需检查覆盖 PostgreSQL 14/MySQL 8.0 最低支持线和 PostgreSQL 17/MySQL 8.4 当前主线。除原有认证、参数绑定、只读、TLS、超时和取消检查外，测试会：

1. 启动一个 30 秒只读等待查询；
2. 在查询进行时重启对应容器；
3. 确认客户端在模板时限内得到脱敏失败结果；
4. 等待服务恢复并重新执行连接检查；
5. 退出时删除两个容器、证书和临时目录。

此脚本要求 Docker、Bash、OpenSSL 和联网拉取测试镜像的能力，不在普通用户启动时运行。

## 仍需人工观察的边界

自动化不能替代以下真实体验检查：

- 笔记本休眠、切换网络和系统代理变化后的主观恢复体验；
- Windows、Ubuntu 和 macOS 桌面账号中系统凭据库的锁定或授权提示；
- 长时间运行时风扇、耗电和界面流畅度等设备相关感受；
- 真实业务系统是否把已接收的远程操作回滚。

这些项目记录在真实桌面验收 Issue 中，不通过在正式代码中加入诊断后门或放宽失败关闭规则来替代。
