# SecretBridge 安全模型与验收

[项目首页](../../README.zh-CN.md) / [文档中心](../README.md) / 安全模型

SecretBridge 的安全目标是限制正常产品接口：AI 可以请求本机代理使用凭据完成任务，但不能通过 Web、MCP 或导出功能读取凭据原文。安全控制服务于功能，不建设单独的认证、试点或证据管理产品。

## 保护对象

- 密码、API令牌、SSH私钥、Cookie和短期认证材料；
- 已解析的命令参数、环境变量、临时文件和协议认证字段；
- 可能回显秘密的 stdout、stderr、错误、日志和历史；
- 用户对连接、任务、有效期和执行次数的授权决定。

## 信任边界

| 主体 | 默认信任 | 能力边界 |
|---|---|---|
| 本机用户 | 可信 | 录入/清除秘密、配置任务、作出授权决定 |
| Web 控制台 | 配对后可信 | 管理配置和任务；仍没有秘密回读接口 |
| 后台代理 | 可信执行面 | 可在运行期间从系统凭据库取密并代用 |
| AI/MCP 客户端 | 不信任其保密能力 | 不能访问原始 PTY、秘密、TOTP 绑定材料或 Web 审批面；只通过 MCP 读取脱敏结果，并可转交用户为指定审批主动提供的一次性验证码 |
| 安全连续终端 | 用户代码执行面 | 普通命令与获批凭据命令可复用同一 Shell；凭据只由代理临时注入 |
| 目标服务 | 仅信任必要协议行为 | 可能失败或回显认证信息，输出必须经过筛选 |

## 必须随功能保留的控制

1. 不提供读取、导出或枚举秘密原文的 API/MCP 工具。
2. 密码、令牌和密钥放入操作系统凭据库，SQLite只保存引用和状态。
3. Web 默认只监听本机；写操作需要有效会话和精确 Origin。
4. 终端输出先经过代理的跨分片脱敏，再进入回放缓冲区、Web 或 MCP。
5. AI 只提交连接、精确命令和凭据占位符；用户可直接审批动态草案，不必预建模板，AI 请求中不包含秘密值。
6. 代理先为终端登记本次使用的秘密，再用私有临时材料完成注入；写入 PTY 的命令和 Shell 历史不包含秘密原文。
7. 模板/连接变化使旧授权失效；运行支持幂等、超时、取消和明确终态。
8. 临时环境和临时文件在完成、失败、取消和启动恢复时清理；终端脱敏模式保留到会话关闭。
9. TLS、SSH 主机密钥等目标身份验证默认启用，不静默降级。
10. TOTP 种子只存放在操作系统凭据库；验证码按审批 ID 和乐观版本提交，使用持久化时间步防重放，并受失败限流约束。MCP 无法生成验证码或读取绑定材料。
11. 首次初始化必须设置至少 6 位的 PIN/口令，之后可选择绑定 TOTP；绑定或解绑 TOTP 不删除 PIN。PIN 验证失败满 5 次后等待 30 秒，持续错误按指数增加至最多一小时，计数和期限持久化；短 PIN 仍可能遭遇数据库副本的离线猜测，推荐较长口令。详细诊断记录写入时使用公钥加密，数据库只保存密文、PIN 与恢复密钥分别封装的私钥及公开加密参数；PIN 和恢复密钥经 Argon2id 派生包装密钥。首次设置后仅显示一次高熵恢复密钥，用户应保存在安全位置。正确恢复密钥可重置 PIN 并保留旧诊断，随后旧恢复密钥失效。TOTP 种子仍仅存于操作系统凭据库。
12. 诊断导出要求已登录的本机 Web 会话和 PIN，事件与完整命令配置由用户勾选，命令默认不选。导出为明文 JSON，可能含地址、路径和业务参数；注入的凭据值、TOTP 密钥和 PIN 不写入诊断记录。固定错误分类与聚合计数仍可在诊断概览中查看，不能将其当作完整日志。详细记录最多保留最近 2,000 条。
13. MCP 桥接只连本机 IPC。Windows 数据目录、桥接连接文档和命名管道使用受保护的 DACL，仅给当前用户和 LocalSystem 访问权，并拒绝远程管道客户端；读取连接文档前重新检查目录和文件权限。Unix socket 所在目录与 socket 分别使用私有权限。IPC 连接仍须验证轮换的桥接令牌。

项目尚未正式发布。若旧持久化格式无法满足现行安全约束，启动时明确拒绝该格式；不为了兼容旧数据恢复较弱的认证或权限路径。

凭据任务、PostgreSQL 检查和验证码校验的原生凭据读取最多等待 15 秒，并限制同时占用的阻塞读取线程；任务取消后不再把迟到的秘密交给执行器。凭据引用及验证码种子的原生写入和删除也最多等待 15 秒。凭据引用超时后保持不可执行，迟到写入会在串行门内清理，迟到删除不能覆盖后续重试。验证码绑定只在 PIN 模式中开始；超时的种子写入先清理才允许重试，解绑则先切回仍有效的 PIN 模式，再删除种子。操作系统弹出的凭据库授权窗口本身不能由当前进程强制关闭；超时只停止请求端等待，不等同于取消底层系统调用。若系统拒绝删除，种子可能暂留在系统凭据库，但 PIN 模式不会再使用它；需在解锁凭据库后清理。

## 注入风险

SecretBridge 对动态命令和固定模板使用相同的四种注入方式，UI 明确说明差异：

- 原生协议或标准输入通常优先；
- 环境变量可能被同用户进程读取，只作用于本次程序调用并在结束后恢复；
- 命令参数可能出现在进程列表中，必须显式选择；秘密通过临时材料取值，不写入 Shell 历史；
- 临时文件必须使用私有目录、最小权限，并在异常恢复时删除；
- 任何方式都必须经过同一输出脱敏和审计边界。

不因为某种方式不完美就阻止所有功能，也不把风险提示写成“绝对安全”承诺。

## 明确不保证的范围

如果 AI 或其他程序已经拥有凭据所有者同一操作系统账号下的任意代码执行权限，它可能直接调用系统凭据库、读取进程内存、调试代理或绕过 SecretBridge。这超出单机同用户应用能够完全解决的范围。

当前产品承诺的是：秘密没有读取或导出接口，代理只在用户配置和授权的任务中代用凭据；命令输出在保存和返回前过滤已绑定秘密的原文及明确支持的编码形式。过滤不是万能的秘密识别，不保证 Base64、加密、自定义变换、未绑定敏感数据或恶意程序主动外传；详见[凭据命令任务](../user-guide/tasks/凭据命令任务.md)。未来可通过专用服务身份和操作系统权限进一步增强，但它不是核心功能开发的前置阻断项。

## 功能开发期间的验收

每个凭据功能至少覆盖：

- 未配对、错误 Origin、过期会话和越权请求被拒绝；
- 设置秘密后响应不含原文，SQLite和普通日志不含原文；
- AI 工具 schema 没有凭据读取接口；审批确认只接受用户为指定待审批请求主动提供的单次 TOTP 验证码，缺少验证码时不能批准自己的请求；
- 模板版本、授权有效期、幂等和取消行为正确；
- 终端输出在任意位置分片时不会直接回显该会话已绑定的秘密；
- 执行失败、超时、取消和服务中断会清理临时材料；
- 连接器只返回约定字段或稳定错误代码。

测试使用合成秘密。真实服务测试使用临时、最低权限账号，测试值不提交到仓库。

## 发布前集中验收

核心功能达到 Beta 后集中完成：

- Windows、Linux、macOS 凭据库与安装目录权限；
- IPC、会话重放、审批绕过和同用户限制说明；
- 编码、分片、输出洪泛、崩溃恢复和长时间运行；
- 依赖漏洞、许可证、SBOM、校验值和确定性打包；
- 安装、升级、回滚、卸载和诊断包检查。

这些内容以开发测试、CI和发布清单维护，不重新建立面向普通用户的证据中心。

## 泄露事件处理

发现可能泄露时：停止相关新任务，撤销或轮换源系统凭据，保存不含秘密的最小诊断信息，确认可能执行的远端操作，修复输出或注入链后使用合成秘密复测。未经用户明确要求，不重写 Git 历史或删除业务系统记录。
