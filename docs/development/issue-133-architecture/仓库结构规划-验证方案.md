# 仓库结构规划：可执行契约与验收

[总览](./仓库结构规划.md) · [职责边界](./仓库结构规划-职责与契约.md) · [服务端迁移](./仓库结构规划-服务端迁移.md) · [其他文件迁移](./仓库结构规划-其他文件迁移.md)

issue #133 是结构重构，不是功能缩减。以现有行为作为功能参考，并针对新版本实际契约运行测试；旧版二进制、安装目录、数据库与内部 API 均不要求兼容。用合成凭据、临时数据目录和回环测试服务，绝不访问已有本机凭据。

## 事实源和测试位置

| 契约 | 唯一事实源 | 可执行检查 | 目标位置 |
|---|---|---|---|
| HTTP | Rust Router 注册、请求/响应 DTO | 枚举真实路由/方法；向内存 Router 发请求，检查成功、错误、认证和 Origin | `backend/tests/http_contract.rs` |
| Web 类型 | 由同一 Rust HTTP 契约导出的机器可读规范 | 生成 `frontend/src/api/generated/contracts.ts` 后比较工作树；TypeScript 编译；浏览器关键流程 | `tools/contracts/generate_http_contracts.py`, `frontend/src/api/generated/contracts.ts`, `tests/contracts/test_generated_web_types.py` |
| MCP | 运行中的 MCP `tools/list` 与工具调用 | 比较工具名称、描述、完整输入/输出 schema；对合成场景执行工具并检验结果/错误 | `backend/tests/mcp_contract.rs` |
| 本机 IPC | 实际客户端/服务端连接和帧解析器 | 协议版本、合法/非法帧、权限、身份、重放和超时在 Windows 与 Unix 分别执行 | `backend/tests/native_ipc_contract.rs` + `backend/local-access` 平台测试 |
| SQLite | 新版创建的临时数据库 | 版本、表、列、索引、外键、约束、备份/恢复和敏感值不入库 | `backend/tests/persistence_contract.rs` |
| CLI/发行 | 新版二进制、服务状态、安装清单和 MCP 启动命令 | 全新安装、启动、停止、卸载；不留下悬空可执行文件路径 | `backend/tests/cli_contract.rs` + `tests/release/` |

Rust HTTP DTO 是网络类型的事实源。重构时引入从**真实 DTO 与路由注册**导出的规范及确定性生成器；规范本身可保存为审阅产物，但不另手写一套字段。生成依赖的具体选型须符合仓库许可政策并锁定版本。`schema` 类型测试应覆盖可空字段、枚举值、默认值、错误响应和分页/游标，不只比名称。Web 私有 view model 仍可手写。

## 必测行为

1. **HTTP：** 实际 Router 的路径/方法全集、状态码、响应字段、WebSocket 升级；未配对、已配对、失效会话、跨 Origin 与错误输入分支。对新版本使用合成夹具运行；有意更改的对外行为须记录。
2. **MCP：** `tools/list` 的工具全集及规范化完整 schema；`tools/call` 的待审批、拒绝、批准、取消、结果游标、失效版本与错误提示。Skill 中的关键示例要能通过真实工具调用，不只检查文案存在。
3. **本机 IPC：** 版本 2 的帧语义、长度上限、令牌与同用户权限、连接文件创建和删除、重放/过期/错误身份拒绝；Windows 命名管道与 ACL、Unix socket 与权限各自实测。未知协议版本明确拒绝。
4. **数据库：** 从空库建立新版 schema，检查真实 `sqlite_master`、`PRAGMA`、索引、外键、唯一约束和事务回滚。备份/恢复在同一新版内对等，凭据值不得进入 SQLite、备份或普通日志；无需读取旧版数据库。
5. **Web：** 生成类型与服务器规范零漂移；Chromium、Firefox、WebKit 覆盖配对、凭据写入、目标/模板、审批、运行/取消、实时终端、设置和恢复。HTTP 与 UI 测试分别承担网络契约与用户流程，不让 mock 掩盖服务端偏差。
6. **安全边界：** 回环监听、OS 凭据库只写不可回读、人工审批不由 MCP 自批、秘密跨分片脱敏、取消后不可继续输出、错误码不泄漏目标/凭据。`backend/local-access/` 的 Windows ACL 与 Unix 权限测试分别执行；Windows unsafe 边界继续单独审阅。

基线捕获不得把用户环境的凭据或私有路径写入快照。需要持久化的测试样本只放合成数据与规范化字段。对于本机 IPC/真实凭据库等无法在所有 CI 平台完整运行的检查，报告平台、环境和未执行范围，不用模拟结果冒充实机证据。

## 执行顺序和完成标准

整个目标状态在一个完整实施 PR 中交付；PR 内按如下顺序推进，任何阶段失败都修复后继续，不把半成品当完成：

1. 从当前 `main` 及现有草稿核实公开契约、记录合成基线；区分现有行为和仅在文档中设想的功能。
2. 完成包名/二进制名、服务/适配器、Web 和文档迁移；一次性更新 Cargo 清单、锁文件、脚本、CI、Skill、安装清单与全部链接。旧安装和旧 MCP 命令保持不动；新版本提供独立的全新安装说明，不做双路径兼容。
3. 跑仓库/许可检查、Python 单测、Web 格式/类型/单测/构建、Rust 格式/测试/Clippy、打包与复现检查；再跑 HTTP/MCP/IPC/SQLite 合约及浏览器验收。
4. 在 Windows 实机验证新版全新安装、启停与卸载、命名管道 ACL、原生凭据库；Linux/macOS 依可用机器分别验证 Unix socket、权限、PTY、系统凭据库。未执行者明确列为后续外部验证，不宣称跨平台全通过。
5. 输出文件归属核对表、路由/工具/schema 契约、测试命令与结果；不存在仅转发旧路径的壳、过时命令、断链或临时拆分脚本。

任一对外契约确需改变，须单独列出原因和新版使用方式；无需提供旧版迁移步骤。上述清单是目标状态验收框架，可增补测试，不以文件名限制未来实现。
