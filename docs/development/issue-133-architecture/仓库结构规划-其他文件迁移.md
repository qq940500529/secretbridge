# 仓库结构规划：Web 与仓库文件逐项迁移

[总览](./仓库结构规划.md) · [职责边界](./仓库结构规划-职责与契约.md) · [服务端迁移](./仓库结构规划-服务端迁移.md) · [验证方案](./仓库结构规划-验证方案.md)

本表描述 issue #133 完成时的归属，不表示文件已经迁移。路径相对于仓库根目录；Web 小节左侧省略现有 `web/src/` 前缀，右侧省略目标 `frontend/src/` 前缀。一个源文件对应多个目标表示按职责拆分，而非复制。对内部路径不留兼容壳；调用、测试、脚本与文档链接同步更新。实施中允许增设必要文件，但不能把未归属代码塞入新的大杂烩。

## Web：应用、API 和通用组件

| 现有文件 | 目标文件 | 归属 |
|---|---|---|
| `main.tsx`, `vite-env.d.ts` | 原位置 | Vite 入口与类型声明 |
| `App.tsx` | `app/App.tsx`, `app/Navigation.tsx` | 页面路由/导航；业务面板移入功能目录 |
| 草稿 `features/shell/components.tsx` | `features/auth/PairingRequired.tsx`, `features/terminal/TerminalLoading.tsx`, `shared/ui/StatusPill.tsx` | 按配对、终端、跨功能状态展示拆分，不保留含混的 shell 容器 |
| `TaskWorkspace.tsx` | `app/TaskWorkspace.tsx`, `app/HistoryWorkspace.tsx` | 拆开两个导出，仍只组合功能页 |
| `styles.css` | `app/styles.css` + 相关组件局部样式 | 全局 token/重置归 app；功能样式贴近所有者 |
| `features/shell/copy.ts`, `ui-copy.test.ts` | `app/copy.ts`, `app/copy.test.ts` | 全局导航与通用界面文案；业务文案留在功能内 |
| `preferences.ts`, `preferences.test.ts` | `app/preferences.ts`, `app/preferences.test.ts` | 本机 UI 偏好与测试 |
| `pairing.ts`, `pairing.test.ts` | `app/pairing.ts`, `app/pairing.test.ts` | 浏览器配对页面状态；服务端调用走 `api/session.ts` |
| `service-events.ts`, `service-events.test.ts` | `app/service-events.ts`, `app/service-events.test.ts` | 应用层事件订阅与重新连接 |
| `api.ts`, `api/client.ts` | `api/{index,transport,session,credentials,targets,templates,approvals,runs,terminals,events,maintenance}.ts` | 按真实 HTTP 资源拆请求；传输/错误/认证只在 transport；`index` 只显式导出 |
| `api/models.ts` | `api/generated/contracts.ts` + 各功能私有 view model | HTTP DTO 由服务端契约生成；页面派生状态不进入网络类型 |
| `api.test.ts` | `api/{transport,session,credentials,targets,templates,approvals,runs,terminals,events,maintenance}.test.ts` | 依请求所有者分测试；关键端到端另由浏览器验收覆盖 |
| `Workbench.tsx`, `workbench.test.tsx` | `shared/ui/{EditorDialog,MasterDetail,SectionTabs}.tsx` 及各自 `.test.tsx` | 三个真实跨功能组件独立维护；删除原聚合文件 |

`frontend/src/api/generated/contracts.ts` 的输入是后端代码生成的机器可读 HTTP 契约，不是另一份手写模型；生成器、锁定版本和差异检查纳入 CI。未在 HTTP 上传输的本机表单/状态类型继续由功能模块维护。

## 文档：按读者问题重组

文档不再沿用原来按文件名粗搬的表格；每篇现有页面的精确去向、需要拆分或合并的章节、导航与链接验收，单列于[文档体系规划](./仓库结构规划-文档体系.md)。尤其把安全模型与测试步骤分开，把 `AI操作Skill.md` 的用户接入与维护者契约分开，把 `开源治理与发布.md` 的治理规则与发行步骤分开。根 README、法律入口和版本范围说明不因目录整齐而被埋藏。
