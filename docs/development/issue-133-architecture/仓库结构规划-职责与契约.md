# 仓库结构规划：职责与依赖契约

[总览](./仓库结构规划.md) · [服务端迁移](./仓库结构规划-服务端迁移.md) · [其他文件迁移](./仓库结构规划-其他文件迁移.md) · [验证方案](./仓库结构规划-验证方案.md)

本文描述 issue #133 的**目标状态**，不是当前代码状态，也不是未来增设文件的限制。可以深度重构，不为旧内部路径保留转发层；已经对外发布的行为仍需通过可执行契约证明不变。

## 服务端依赖方向

```text
HTTP / MCP / 本机 IPC 入站适配器 ──► 应用用例 ──► 领域模型与纯规则
                                          │
                                          └──► 应用端口（特定外部能力）
                                                     ▲
                         SQLite / 凭据库 / 执行器 / PTY 出站适配器

运行时组合根负责装配两端；CLI 只调用运行时入口。
```

| 层 | 拥有内容 | 可依赖 | 禁止依赖 |
|---|---|---|---|
| `domain/` | 凭据引用、连接、任务、审批、运行、事件的业务含义；纯校验和策略判定 | 标准库、必要的纯数据类型 | Axum、MCP、SQLite、密钥链、PTY、Web |
| `application/` | 配对与会话、凭据状态转换、审批、执行与取消、脱敏、终端租约、备份恢复的用例 | domain、明确的 `ports.rs` | HTTP 路由、MCP 工具宏、具体 SQL、平台 API |
| `adapters/http/` | 路由、Origin/会话入口校验、请求响应 DTO、WebSocket、HTTP 错误码 | application、domain | 直接操作 SQL 或原生凭据库 |
| `adapters/mcp/` | 工具注册、MCP schema/DTO、JSON-RPC 错误映射、对话工具语义 | application、domain | 直接调用 HTTP 处理器或本机 IPC 实现 |
| `adapters/native_ipc/` | 桥接协议、连接生命周期、令牌/身份规则及与本机端点交互 | application 的受控入口；`backend/local-access/` 的 OS 权限 API | 把 IPC 令牌暴露为 MCP 工具结果，或自行复制平台 ACL/模式位实现 |
| 出站适配器 | SQLite、密钥链、协议执行、PTY 与平台差异 | application 端口、domain | 反向调用 HTTP/MCP 处理器 |
| `runtime/` | 启停、依赖装配、运行状态及本机诊断 | application、adapters | 实现新的业务规则 |

`application/ports.rs` 只定义用例真正需要的外部能力：配置存储、秘密值存储、受控执行、终端和时钟/事件。一个端口的接口应围绕具体用例，而不是把完整 `Catalog` 暴露给所有服务。没有测试替身或独立实现价值的调用不强制套一层 trait。

## 关键所有权

| 当前易混职责 | 唯一目标所有者 | 判断依据 |
|---|---|---|
| `AppState` 中的所有组件和锁 | `runtime/composition.rs` | 只装配、持有和关闭，不实现配对、审批或执行逻辑 |
| 会话发行、认证、撤销 | `application/sessions.rs` | HTTP 和运行时入口共享相同规则；HTTP 只提取凭证、映射响应 |
| 授权模式、参数冻结、审批/运行状态机 | `domain/policy.rs`、`domain/approvals.rs`、`domain/runs.rs` | 无数据库连接参数的纯规则进入 domain |
| 依赖数据库查询才能判定的策略 | `application/authorize.rs` | 读取所需快照后调用纯规则，不把 SQL 写入 domain |
| 跨 SQLite 与密钥链的凭据写入 | `application/manage_credentials.rs` | 唯一协调锁、版本、不可用态、原生写入及失败补偿 |
| 运行创建、复核、取消、清理 | `application/execute_run.rs` | HTTP 和 MCP 调同一用例；执行器只执行已获准的固定请求 |
| 秘密回显过滤 | `application/redaction.rs` | 在编码、持久化及返回前共同调用；执行器不得自行放宽 |
| SQL、迁移、行映射、备份数据校验 | `adapters/persistence/` | 只负责持久化与事务，不定义对外业务契约 |
| 原生凭据库及测试内存实现 | `adapters/secrets/` | 只有写、覆写、删及受门控读取；不提供导出端口 |
| MCP 的工具协议 | `adapters/mcp/` | 工具 schema 和结构化结果，不包含桥接连接文件规则 |
| 本机桥接协议和权限 | `adapters/native_ipc/` | MCP 和 CLI 可作为调用方，但桥接安全边界独立 |
| 本机数据与 IPC 的 OS 权限 | `backend/local-access/`（`secretbridge-local-access` Cargo 包） | Windows ACL FFI 和 Unix 文件/socket 权限采用同一窄接口；unsafe 限定在 Windows 模块。令牌、重放及授权仍属 `adapters/native_ipc/permissions.rs` |

领域对象只有一份业务定义。SQLite 行结构私有于 persistence；HTTP/MCP DTO 只表达真实的传输差异，使用显式转换。不得再把数据库行或某个传输请求当作领域模型的事实源。

当前 `secretbridge-core` 仅有主包一个生产使用者，不能因为名字叫 `core` 就把它当领域核心。目标取消该包：运行模式归 `application/status.rs`，HTTP 状态响应与 API 版本归 `adapters/http/`，SQLite schema 版本归 `adapters/persistence/schema.rs`，由构建/发行元数据按只读接口引用。主程序直接放 `backend/`，Cargo 包名为 `secretbridge`；本机权限组件是其内部辅助包 `backend/local-access/`，不与前端/后端平级。若将 `synthetic_runs` 实体表改名，则正式升级 schema 版本并验证旧库与备份迁移，不能仍声称磁盘格式不变。

## Web 所有权

| 位置 | 拥有内容 | 不得承担 |
|---|---|---|
| `app/` | 启动、导航、配对页面状态、语言偏好、服务变更订阅 | 凭据或任务业务表单 |
| `api/transport.ts` | `fetch`、统一错误与认证头 | 某个功能的字段和文案 |
| `api/{session,credentials,targets,templates,approvals,runs,terminals,events,maintenance}.ts` | 对应领域的请求函数 | 所有接口集中到新的 `tasks.ts` |
| `api/generated/contracts.ts` | 从服务端公开 HTTP 契约生成的类型，不手工编辑 | 页面状态或 API 调用实现 |
| `features/tasks/templates/` | 模板列表、编辑与各协议编辑器 | 审批队列或运行历史 |
| `features/tasks/approvals/` | 待确认项、审批详情与 AI 对话授权 | 模板保存或运行输出 |
| `features/tasks/runs/` | 启动、取消、结果、数据库结果呈现 | 模板配置 |
| `features/tasks/shared/` | 确实被模板、审批、运行多处使用的参数和请求预览 | 无边界的“杂项”组件 |
| `shared/ui/` | 跨凭据、任务、设置等功能复用的对话框、主从列表、标签页和状态展示 | 业务 API 或业务文案 |

现有 `Workbench.tsx` 的三种组件确有多个使用者，因此分别成为 `shared/ui/EditorDialog.tsx`、`MasterDetail.tsx`、`SectionTabs.tsx`；其测试按组件拆分。现有 `features/shell/components.tsx` 也按配对、终端和通用状态分别归属。`features/catalog/shared.tsx` 拆为目录布局、资源文案与真正通用的控件。`CommandReview.tsx` 由模板与审批共同使用，归 `features/tasks/shared/`，不放入全站 `shared/`。

## 模块与命名规则

- 允许不同层使用相似业务名，但用例文件采用动词名称（如 `manage_credentials.rs`、`execute_run.rs`）；存储文件名表示表/聚合，HTTP 文件名表示路由资源。
- 不使用 `helpers.rs`、`utils.rs`、`common.rs` 接纳尚未归属的逻辑。现有辅助函数按校验、行映射、策略、协议或文件权限分别归位。
- 同一源文件可拆入多个目标文件，但每个函数只有一个新所有者；迁移对照文档记录源、目标和调用方。
- 单元测试贴近所有者；跨层场景放在 crate 集成测试或仓库验收测试。测试不能通过暴露生产代码内部细节来迁就旧位置。
- 功能新增时可建立新目录或文件；上述清单只描述本次重构完成后的状态。
