# 仓库结构规划：文档体系

[结构总览](./仓库结构规划.md) · [全仓命名审查](./仓库命名与边界审查.md) · [其他文件迁移](./仓库结构规划-其他文件迁移.md)

本文仅规划重构完成后的读者路径和内容归属；当前文档尚未搬迁。目标不是把旧文件重新塞进“项目资料”目录，而是让用户、贡献者、验证者和维护者按任务找到一个权威页面。文档应陈述产品行为、步骤、限制与可核对的证据；不保留开发阶段的提示词—回答口吻，也不在长期页面堆一次性测试日志。

## 目标导航

```text
docs/
├─ README.md                         # 读者导航，不复制各页正文
├─ 开源版与企业版.md                   # 产品范围的一级入口
├─ 最终用户许可与免责声明.md             # 对用户直接可见的法律入口
├─ getting-started/                  # 获取、安装、首次使用
├─ user-guide/                       # 日常操作与任务类型
│  └─ tasks/
├─ security/                         # 威胁模型和边界，不混测试步骤
├─ testing/                          # 可复现的验收与实机验证
├─ development/                      # 架构、参与开发、MCP/Skill 契约
├─ release/                          # 支持范围、打包、供应链门槛、发布
├─ governance/                       # 贡献权利、依赖许可与治理规则
└─ community/                        # 公测反馈与待验证事项
```

`docs/README.md` 提供“安装/使用/开发/验证/发行/反馈”入口，最多一层导航摘要。根 `README.md`/`README.zh-CN.md` 是产品介绍与快速入口，不能复制整份部署提示词或开发清单。详细步骤只在一个权威页面维护，其他页面用链接引入。

## 重组原则与验收

1. 先建立每页的**唯一问题和读者**：安装、日常使用、设计、测试、发行和治理不得用“项目”笼统收纳。若两页处理同一问题，合并或明确“操作步骤 vs 设计依据”。
2. 根 README、`docs/README.md`、`AGENTS.md`、Skill、Issue/PR 模板与 UI 帮助链接一起更新。使用链接检查和搜索旧路径验证；不留断链、过时截图/命令或无内容的转发页。
3. 自动化指南可以面向工具，但应是**维护的运行手册**，明确输入、停止条件和结果；面向人类的指南解释为什么及如何确认。提示词示例不能冒充软件功能描述。
4. 变更部署命令、二进制名或数据库格式时，同步更新所有示例并经真实打包/升级测试；不能只让 Markdown 链接通过。
5. 中英文根 README 保持同等事实。中文详细页可作为当前唯一权威说明；尚未提供英文长文时明确标注语言范围，不自动生成未经审校的重复页面。

这份映射可在实施中依据实际段落微调，但每篇原始文档都必须有可核对的去向，不能因为改目录而遗失法律声明、安全警告或操作步骤。
