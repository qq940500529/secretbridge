# 结构重构契约核对

[架构设计](../架构设计.md) / [结构规划](./仓库结构规划.md) / 契约核对

此核对针对 `0.3.0-beta.2` 源码线，以重构前的 `7abad68` 为功能参照。旧版安装、数据目录和二进制不是新版的迁移输入；新版发行须在全新目录验收。

| 契约 | 重构前 | 当前实现 | 自动化检查 |
|---|---|---|---|
| HTTP 路由路径 | 34 个 `/api/v1/` 路径 | 原路径均保留，增加 `/api/v1/session/recover` 与 `/api/v1/session/recovery-key` 两个 PIN 恢复端点 | `tests/contracts/test_http_routes.py` 固定路径全集；`backend/src/adapters/http/tests.rs` 检查鉴权、Origin、响应和失败分支 |
| MCP 工具与 schema | `mcp.rs` 统一注册 | 迁至 `backend/src/adapters/mcp/`，工具语义与服务端审批边界保留 | `advertises_only_the_bounded_tool_surface`、Skill 示例/schema 校验及 MCP 跨层调用测试 |
| 本机 IPC | 独立 stdio 桥接连接本机代理 | `backend/src/adapters/native_ipc/` 拥有帧收发与连接文件，`backend/local-access/` 负责平台权限 | 桥接鉴权、残留端点、权限及平台测试 |
| SQLite | schema 23 | schema 24 增加恢复密钥包装列与持久化 PIN 失败计数/等待期限；这是 PIN 功能的明确行为变化 | 空库、恢复、PIN 错误等待、密文诊断和备份测试 |
| Web 关键流程 | `web/src` 混合页面与 API | `frontend/src/app`、`api`、`features` 与 `shared/ui` 分责；首次许可与 PIN 现在同一引导页 | Web 单测、类型检查与 Chromium/Firefox/WebKit 浏览器工作流 |
| 发行路径 | 旧包名与脚本位置 | 主程序为 `backend/` 中的 `secretbridge`；Skill 随发行包提供，打包与检查脚本按职责归档 | 发行包清单、摘要、复现构建、安装/升级/回退/卸载验收 |

公开 API 的有意新增仅为 PIN 恢复；登录失败时新增 `429` 与 `Retry-After`。首次设置 PIN 返回仅显示一次的恢复密钥；变更已有 PIN 仍返回无内容。没有恢复密钥的旧包与 schema 23 不在新版兼容承诺内。

仓库检查、Python、Web、Rust、浏览器与安装包测试各自覆盖不同边界，不能由一个门槛代替另一个。真实桌面、原生凭据库及不同系统账号的检查按[社区验证待办](../../community/社区验证待办.md)单列，不将无头浏览器或模拟服务记录成实机结果。
