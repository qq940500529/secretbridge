# 持续集成检查范围

仓库的检查按变更内容选择，规则由 [`tools/checks/change_scope.py`](../../tools/checks/change_scope.py) 实现，并通过单元测试约束。检查范围只影响运行时间，不降低发行门槛：标签发布工作流始终执行完整的跨平台构建与验收。

| 变更内容 | 主要检查 |
|---|---|
| 纯 Markdown 等文档和文档图片 | 仓库内容、项目元数据、检查范围规则测试 |
| Web 前端 | Web 格式、类型、测试与构建；浏览器验收；原生包交付 |
| Rust 后端 | Rust 格式、测试与 Clippy；按模块追加数据库连接器、Python 契约或浏览器验收；原生包交付 |
| Python 工具和测试 | 对应 Python 格式、静态检查与测试；涉及发行、依赖或验收时还运行相关检查 |
| 依赖清单、锁文件、安全策略、CI 配置 | 完整检查 |
| 未知路径、无法比较提交、手动或定时运行 | 完整检查 |

路径规则采用保守策略。只有明确列入文档白名单的变更才会跳过重型检查；新增文件类型或目录若没有规则，会触发完整检查。需要修改规则时，同时更新分类器单元测试，确保相关检查不会被误跳过。GitHub 中被跳过的 job 保持可见，便于审阅者区分“未受影响”与“检查失败”。
