# 工作台设计体系

[文档中心](../README.md) / [跨平台与 UI 规范](./跨平台与UI规范.md)

秘桥是本机执行代理的管理工作台。界面的第一目标是让用户准确判断“将对哪个目标、用哪个凭据、执行什么、返回什么、是否已经获批”。配置、决定和复盘应各有位置，不靠大量卡片解释自身。

## 任务流与信息架构

```mermaid
flowchart LR
    C[连接与凭据\n目标、引用、检查范围] --> T[任务\n固定操作与参数]
    T --> A[审批\n快照、风险与有效期]
    A --> R[执行\n技术状态与结果验证]
    R --> H[历史\n事件、运行输出与关联标识]
```

主导航只承载“连接与凭据、任务、终端、历史、设置”五个工作域。连接与凭据、历史、设置在各自工作域内用二级分区切换；审批属于任务流，但未处理数量在全局顶部持续可见。顶部只显示服务、配对与剩余有效期等跨页面状态。页面级标题、说明和一个主要动作组成稳定首部。

| 区域 | 承载内容 | 不承载内容 |
|---|---|---|
| 主列表 | 名称、目标、状态、时间；检索与过滤 | 整份命令或终端流 |
| 详情 | 当前记录的含义、范围、结果与关联 | 创建表单与危险操作的默认展开 |
| 右侧编辑面板 | 创建或编辑配置，提交与取消 | 决定性审批 |
| 居中审批模态 | 不可变操作快照、风险、有效期、备注与决定 | 独立于快照的第二份可编辑配置 |
| 运行历史 | 按运行/审批/终端/时间定位，分层输出与下载 | 安全事件列表的重复长输出 |

审批模态限制在视口高度以内：标题和决定栏保持可见，仅快照正文滚动。浏览器后台无法保证自动抢焦点；因此待办数字和标题是持久回退，通知只是辅助提示。任何执行成功的绿色状态只描述进程或驱动调用；业务预期是否满足须单列校验状态。

## 页面线框

```text
┌──────────────────────────────────────────────────────────────────┐
│ 服务状态 · 配对剩余                             待审批 · 语言 │
├───────────┬──────────────────────────────────────────────────────┤
│ 连接与凭据│  连接 [凭据]                 页面级主要动作        │
│ 任务      │  标题 / 一句话说明                                  │
│ 终端      │  搜索、筛选                                         │
│ 历史      │  ┌────────列表────────┬────────详情────────────┐  │
│ 设置      │  │ 名称、状态、时间    │ 范围、下一步与关联      │  │
│           │  └───────────────────┴──────────────────────────┘  │
└───────────┴──────────────────────────────────────────────────────┘
```

窄视口优先保留目标、决定和结果，不将关键操作裁切在横向滚动区域。无终端时展示紧凑引导，不显示空黑屏；配置高级字段与危险操作按需展开。凭据秘密值只在用户主动更换时短暂进入输入区，保存后清空。通用连接元数据与 PostgreSQL 检查配置须明确作用域；通用命令不会自动继承检查用 TLS。

## 视觉与交互约束

颜色 token 定义于 `frontend/src/app/styles.css`：雾白画布、白色工作面、深海蓝导航、玉青色主要操作。成功、警告和危险色只表达状态；焦点轮廓独立于颜色填充。间距以 4/8/12/16/24/32 px 节奏建立，正文以 14–16 px 为主；长标识、代码和原始输出使用等宽字体，但不得替代人能读懂的主标题。

每页优先保留一个主动作。普通编辑按钮放记录上下文；删除、清除秘密、停止服务与全会话授权须隔离、解释影响并在执行前确认。空、加载、错误、已失效、只读和未验证状态都要提供自然语言下一步，技术码留在可展开详情。中文与英文保持同样的信息层级，不因翻译长度改变审批按钮可见性。

## 验收矩阵

自动化浏览器流程检查 320/390/720 px 窄视口、1366×768 与 1920×1080 审批模态、主操作可见、焦点和无横向裁切；组件检查长输出、零行、未达预期、审批快照失效与会话过期。Windows 高 DPI、125%/150% 浏览器缩放、系统通知前台唤起和平台原生凭据库行为需在各平台真实桌面再次确认，不能从 CI 截图推断。

设计依据：[Atlassian Panel](https://atlassian.design/components/panel/usage/) 关于面板上下文与固定操作区、[Carbon Modal](https://v10.carbondesignsystem.com/components/modal/usage/) 关于模态决定的结构、[Linear 设计更新](https://linear.app/now/behind-the-latest-design-refresh) 关于降低视觉噪声；使用的是交互原则，不复刻其品牌或组件。
