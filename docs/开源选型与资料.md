## 框架路线

| 路线 | 已核对的定位 | 密桥的判断 |
|---|---|---|
| 系统浏览器＋本地Rust服务 | 浏览器提供管理界面，Axum服务只绑定回环地址；Web UI与原生执行边界分离 | 已用于M0；不使用桌面壳，浏览器来源校验、会话认证和后端授权同时生效 |
| Tauri／Electron桌面壳 | 可封装Web UI并提供桌面运行时 | 明确不采用；后续规划不得以“可选壳”重新引入 |
| 在KeePassXC上改造 | 现成密码管理与集成功能，可查官方手册与CLI资料 | 不直接fork作为终端代理；它解决凭据管理，并不自动解决AI执行策略与输出控制。可后续作独立SecretStore来源，许可证与集成协议需另核 |
| OpenBao后端 | 提供秘密、证书、密钥管理，仓库为MPL-2.0 | 适合未来团队／服务器集中管理；个人本机MVP暂不增加部署负担，不向AI直接暴露其取密token |

来源：[Axum文档](https://docs.rs/axum/0.8.9/axum/)、[React版本](https://react.dev/versions)、[Vite指南](https://vite.dev/guide/)、[KeePassXC官方资料](https://keepassxc.org/docs/)、[OpenBao仓库](https://github.com/openbao/openbao)。

上述判断来自密桥的功能与安全需求，而非宣称某框架天然比另一框架安全。优先复用成熟组件，但不继承不适合本项目的“一键填充到任意窗口”或“AI直接读秘密”接口。

## 组件职责与验证点

| 组件 | 用途 | 实现前验证 |
|---|---|---|
| Rust 1.98＋Axum 0.8.9＋Tokio 1.53 | 回环Web服务、认证会话与后续执行监督 | 只绑定回环地址；拒绝错误Origin和令牌；服务权限仍需三平台隔离实验 |
| React 19.3＋TypeScript 7.0＋Vite 8.3 | 中英文配置、审批与状态页面 | 密码不进持久store、浏览器存储、日志或埋点；构建产物只含本地静态资源 |
| Tailwind CSS 4.3＋Radix Tooltip 1.2＋Lucide React 1.44 | 响应式布局、可访问交互与图标 | 键盘、屏幕阅读器、主题和图标许可证随锁文件复核 |
| xterm.js 6 | 已用于合成终端的文本与交互展示，MIT许可证 | 控制序列、剪贴板、链接、插件及前后端信任边界 |
| portable-pty／ConPTY | Windows ConPTY及Linux/macOS POSIX PTY | UI断开后的生命周期、中文编码、resize、大输出和进程树取消 |
| Windows Credential Manager／DPAPI | 可替换的本地SecretStore实现 | 专用身份范围、ACL、服务用户配置文件、备份恢复、同账号绕过实验 |
| SQLite 3.53.2（由rusqlite 0.40.2 bundled） | 非秘密元数据与后续策略版本、审查后事件索引 | 已用于凭据引用和逻辑目标；模式不含秘密或端点列，继续验证ACL、迁移、崩溃一致性与磁盘配额 |
| 自有轻量MCP适配层 | 标准工具协议接入AI宿主 | 使用stdio，不能因宿主退出杀掉后台代理；不向工具返回秘密 |

具体版本见`Cargo.lock`与`pnpm-lock.yaml`。SQLite与portable-pty已经锁定并用于开发原型；凭据库封装、MCP SDK及数据库／SSH适配库尚未引入。每项首次引入的PR必须固定版本、更新第三方声明并说明平台与许可验证。跨平台封装只解决接口差异，不能据此假设持久化、隔离或进程生命周期已经满足验收。

## 技术依据

1. [OWASP CSRF防护建议](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)要求来源验证、Fetch Metadata或令牌等纵深措施。故回环服务仍检查精确Origin并要求一次性启动令牌，后续还要增加会话撤销、期限与Fetch Metadata测试。
2. [xterm.js安全说明](https://xtermjs.org/docs/guides/security/)说明终端集成涉及前后端与输入输出风险。故只用作渲染器，不给予凭据获取能力，不把展示过滤当安全边界；[仓库](https://github.com/xtermjs/xterm.js)用于后续版本及许可证核对。
3. [ConPTY创建会话](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session)提供Windows伪控制台生命周期与管道机制；[portable-pty源码](https://github.com/wezterm/wezterm/tree/main/pty)作为封装候选。持久化由密桥监督器设计，不是ConPTY自动替应用完成。
4. [CredReadW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credreadw)与[CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)说明凭据访问与系统保护上下文。故不承诺同Windows身份任意代码无法读密。
5. [命名管道访问控制](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)说明管道安全描述符与访问检查。故采用显式DACL而非仅凭“localhost／本机”判定可信。
6. [MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)规定stdio和Streamable HTTP等传输约定；此链接为明确版本的规范，不宣称它永远是最新。首版选择stdio并把诊断与协议输出分开，未来HTTP接入需独立认证与来源校验。
7. [PostgreSQL环境变量](https://www.postgresql.org/docs/current/libpq-envars.html)不建议用PGPASSWORD；[password file](https://www.postgresql.org/docs/current/libpq-pgpass.html)说明另一认证来源。故优先协议适配，临时文件仅例外，不把环境变量注入宣传为安全完成。
8. [OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)为最小权限、轮换、撤销与日志处理提供参考。项目的威胁表与测试条件是自己的实现要求，未获得OWASP或第三方认证。

## 依赖引入流程

1. 说明待解决问题与候选组件的最小必要功能。
2. 核对确切版本、许可证、维护状态与已知漏洞。
3. 使用合成数据完成平台实验，记录限制与失败案例。
4. 更新锁文件、第三方声明和测试，不引入真实凭据或业务配置。
5. 若影响权限或秘密生命周期，附安全设计评审。

pnpm对新发布版本设置24小时等待期并严格执行；本次确需采用的当日稳定版以“包名＋精确版本”登记例外，升级后旧例外应删除。这只是降低供应链突发风险，不替代来源、签名、漏洞和许可证审查。

依赖记录格式见[第三方声明](../THIRD_PARTY_NOTICES.md)，发布条件见[开源治理](开源治理与发布.md)。
