# 开源治理与发布标准

2026-09-10，设计v0.2。本文件为项目工程与合规流程，不构成法律意见。项目当前为设计阶段，不能声称达到成熟产品质量或已完成安全审计。

## 1. 许可决定

按项目所有者要求采用GNU Affero General Public License v3.0，明确SPDX为 **AGPL-3.0-only**，没有擅自加入“or later”。项目自有代码与文档按此授权；第三方原文、组件与资产保留其许可。完整LICENSE取自GitHub许可API提供的AGPL v3原文，不改动其条文，README的授权声明决定本项目采用only版本。

AGPL允许商业使用，不是禁止商业或禁止竞争的许可证。分发及修改需要遵守适用的源码与许可条件；第13条对修改版通过网络与用户交互时提供对应源码机会作出要求，不能简化为“任何网络调用都必须公开公司的全部代码”。边界以许可证及实际组合方式为准。[AGPL原文入口](https://www.gnu.org/licenses/agpl-3.0.html)、[GitHub许可API](https://api.github.com/licenses/agpl-3.0)

AGPL并不要求上传用户密码、客户数据库、生产配置或无关业务资料。发行可执行程序时同时提供对应版本源码、构建／安装脚本和必要的许可说明；未来UI提供“关于／许可证／此版本源码”入口，远程服务形态需检查相应源码提供机制。

没有新增“禁止商用”等额外限制，没有默认为所有贡献索取版权转让。贡献者须有权提交其内容，以同许可证贡献；使用DCO签署确认来源，但签署本身不能证明权利。AI辅助内容必须披露生成范围并经人工审阅、测试和来源核对；不得把AI输出视为天然无版权风险。涉及职务成果、第三方衍生作品、专利或商标时需单独核验，必要时咨询专业人士。

## 2. 依赖与资产

当前没有应用依赖、复制的框架代码、第三方图片字体或安装包。选型文档中的组件不等于已打包。未来每个直接／间接依赖须登记版本、来源、许可证、分发形态和NOTICE要求；引入代码前先检查AGPL兼容性与实际链接／组合方式。

MIT／Apache等名称不能替代检查具体版本与附带资产许可。不因项目源码公开就默认允许复制；无许可证仓库不直接复制。图片、图标、字体、示例数据、截图、文案同样登记来源。保留第三方通知，生成SBOM并核对打包产物，不只扫描package清单。

## 3. 发布边界与隐私

公开仓库采用独立目录、全新Git历史，不推送个人工作区历史、其他项目、邮件、批处理、数据库导出、终端转储或聊天记录。只发布明确选入的项目文件。提交身份采用GitHub公开用户名和noreply地址，不暴露本机邮箱与个人路径。

先核对发布清单→扫描所有候选文件与Git历史→人工审看→推送公开仓库→检查远端文件、许可证与CI。检测器不输出秘密原值；误提交后先撤销凭据，不能以删除最新文件或强推历史保证消除泄露。

仓库检查工具只做有限的模式与文件检查；后续加入成熟secret scanner并固定版本。GitHub secret scanning／push protection若账号支持应启用并核实结果；不能把默认设置写成已启用。敏感安全报告通过私人报告渠道，不通过公开issue索要真实日志或数据库。

## 4. 仓库质量门槛

| 层次 | 当前可交付 | 后续进入该阶段时必须提供 |
|---|---|---|
| 立项仓库 | 中英文README、设计、安全模型、许可、贡献指南、行为准则、模板、有限仓库CI | 清楚标记无应用、不伪造下载／测试徽章 |
| 代码原型 | 尚未开始 | 三平台构建、Rust/TS静态检查、核心单元与集成测试、锁文件、适配器测试 |
| 安全试点 | 尚未开始 | 威胁模型攻击用例、隔离实验、泄漏测试、模糊测试、所有高危问题闭环 |
| 产品候选 | 尚未开始 | UI可用性／可访问性、原生平台验证、安装卸载、升级回滚、文档与示例 |
| 正式发行 | 尚未开始 | 对应源码、SBOM、哈希、签名、公证、变更记录、兼容矩阵和已知问题 |

测试覆盖率只能作为提示，不是安全证明；不能靠生成大量文档、徽章、空模块或mock通过率代替真实质量。持续维护release notes、问题分级与架构决定。尚未承诺商业SLA或第三方审计。

## 5. CI与仓库权限

当前CI在Windows/Linux/macOS运行文档检查和仓库检查器测试；只授予contents:read，第三方Action固定到完整提交SHA，关闭checkout持久凭据。PR流程不用pull_request_target执行外部代码，不接触生产密钥，不使用带业务资料的自托管runner。

代码实现后补Rust/TS构建、依赖漏洞与许可证检查、成熟secret scanner、代码扫描、单元／集成／安全测试。自动更新工具只发PR，不自动合并安全相关修改。release签名凭据置于受保护发布环境，普通PR不可读取；发布需要人工批准，优先短期凭据，产物关联来源提交。

main建议禁止删除、禁止force push、要求PR和基础CI；维护者人数不足时不伪装已存在双人复核。初次发布后核实平台保护和私人漏洞报告是否生效，失败应记为待办而非静默忽略。

## 6. 发布范围说明

本次仅公开设计阶段仓库与治理／检查工具，不创建0.1.0软件发行、不上传安装包、不宣称运行兼容性。三平台开发和UI实现应按ROADMAP逐阶段验收。完成开源初始化不等于完成用户期待的优秀级软件。
