# 开源版与企业版产品边界

[项目首页](../README.zh-CN.md) / [文档中心](README.md) / 开源版与企业版

SecretBridge 采用双轨产品规划：当前公开仓库交付面向个人用户的本机开源版；未来另行开发面向组织客户的闭源商业企业版。两条产品线共享“让 AI 使用凭据完成获准操作，而不向 AI 返回凭据原文”的核心理念，但服务对象、部署方式和管理能力不同。

本文用于回答三个问题：当前仓库应当交付什么、哪些能力属于未来企业版、如何在持续开源的同时维护清楚的商业产品边界。

## 产品定位

### 开源版

开源版是可独立使用的公开发行产品，不是企业版的演示页或残缺试用版。它面向单个操作系统用户，在一台个人电脑上提供完整的凭据保存、授权、代执行、终端、连接器和脱敏结果工作流。

开源版应达到成熟开源软件的工程质量：跨平台构建、可验证发行物、清楚文档、依赖治理、真实服务测试、升级回滚和问题响应。它不承担组织管理、集中控制和合规平台职责。

### 企业版

企业版是未来单独规划、单独交付的闭源商业产品，面向需要多人协作、统一策略、集中管理、审计与技术支持的组织客户。企业版能力不作为开源版 1.0 的前置条件，也不应拖慢个人本机工作流的完善。

企业版的功能、交付时间、授权方式和支持范围以未来正式商业方案为准。本文列出的企业能力是产品方向，不构成已发布功能承诺。

## 差异总览

| 维度 | 开源版 | 企业版（规划） |
|---|---|---|
| 主要用户 | 个人开发者、运维人员和 AI 工具使用者 | 企业、团队、受管终端和内部平台 |
| 部署范围 | 单机、单操作系统用户、本机回环网络 | 集中管理端、受管执行节点或企业私有部署 |
| 身份模型 | 当前系统用户和本机页面会话 | 企业账号、团队、角色、服务身份和设备身份 |
| 凭据存储 | 操作系统凭据库，本机保存和使用 | 企业密钥系统、集中策略、分级授权及轮换集成 |
| 授权方式 | 用户在本机按任务单次或限时授权 | 角色策略、多人审批、条件授权和组织级例外流程 |
| 执行范围 | 本机终端及用户配置的固定连接器任务 | 多节点调度、受管代理、集中任务编排和策略下发 |
| 连接器 | 面向个人常用场景的 HTTP、SSH、SFTP、Git、PostgreSQL、MySQL 等 | 企业系统、商业数据库、目录服务、工单、堡垒机及定制连接器 |
| 终端 | 当前电脑上的持久终端 | 受管主机、会话策略、集中运维和组织级访问控制 |
| 审计 | 本机运行与固定事件历史 | 集中审计、检索、归档、告警、报表和外部 SIEM 集成 |
| 管理 | 用户自行配置、备份、恢复和升级 | 管理控制台、批量部署、配置下发、设备清单和生命周期管理 |
| 可用性 | 单机可靠运行，用户自行恢复 | 高可用、集中备份、灾难恢复和服务等级目标 |
| 合规 | 清楚说明安全边界并提供必要技术控制 | 根据商业场景提供审计、留存、审批和合规适配能力 |
| 支持方式 | 社区文档、Issue 和公开版本更新 | 商业支持、实施服务、升级策略和约定响应时间 |
| 许可 | AGPL-3.0-or-later；超出开源许可的使用需取得书面商业许可 | 独立商业合同和闭源软件许可 |

## 共同的核心原则

以下原则不因版本不同而降低：

- AI 接口不提供秘密原文读取、导出或列举能力；
- 凭据只在获准任务的执行时刻由可信代理解析和代用；
- 普通命令与获批凭据命令可复用安全连续终端；秘密由代理临时注入，输出在进入 Web 或 MCP 前脱敏；
- 输出、错误、历史和诊断经过敏感信息控制；
- 授权绑定任务、参数和配置版本，支持撤销、超时、幂等与取消；
- 连接器明确声明认证方式、输入、输出、失败语义和清理责任；
- 用户能够理解即将执行的目标、参数、权限和结果范围。

企业版可以增加更强的身份、隔离和治理能力，但不能通过削弱上述原则换取管理便利。

## 开源版 1.0 范围

当前公开仓库以完成以下能力为目标：

- Windows、Linux 和 macOS 上的本机 Web 工作台与后台代理；
- 操作系统凭据库、凭据引用、连接、任务、授权、运行和历史；
- 可重连的真实持久终端，以及 Web 与 MCP 之间的输入协调；
- 固定程序任务和受约束的凭据注入方式；
- HTTP、SSH、SFTP、Git、PostgreSQL 和 MySQL 的明确操作合同；
- 跨分片脱敏、临时材料清理、任务取消和异常恢复；
- 配置迁移、备份恢复、精简诊断、安装升级与回滚；
- 三平台持续集成、真实服务测试、依赖许可检查、SBOM、校验值和离线发行包验证。

当前开源版采用未签名发行包。代码签名、公证和软件源签名不作为 1.0 发布条件；各操作系统可能因此显示未知发布者或安全确认提示，安装文档应如实说明处理方式。

## 不进入开源版近期范围

以下能力属于企业版方向或更晚的独立项目，不进入当前开源版 1.0：

- 多租户、团队空间、组织目录和角色权限；
- 集中凭据中心、跨设备同步和组织级轮换；
- 多人审批、工单联动、集中策略和例外管理；
- 远程控制面、受管代理集群和跨节点调度；
- 集中审计平台、合规证据中心、SIEM 和长期归档；
- 批量安装、设备管理、企业升级通道和服务等级管理；
- 高可用控制平面、集中灾备和企业级容量保证；
- 面向客户环境的定制连接器及商业实施功能。

开源版不会为了制造商业差异而故意限制单用户本机核心功能。版本差异来自企业协作、集中治理、部署规模和服务保障，而不是把本机取密或基础执行能力改成付费开关。

## 代码与贡献边界

公开仓库只保存开源版代码、文档、测试和发行材料。未来企业版的闭源模块、客户配置、商业交付脚本和内部资料不进入公开仓库。

公司自有代码可以按照公司确定的开源或商业许可方式发布。外部贡献是否能进入闭源企业版，取决于贡献者授予的权利和适用许可证；不能仅因代码已经合入公开仓库就推定版权方拥有商业再许可权。具体规则见[贡献与再许可](贡献与再许可.md)和[商业授权说明](../COMMERCIAL_LICENSE.md)。

开发新能力时按以下顺序判断归属：

1. 单个用户在本机完成核心工作是否需要它？需要则优先进入开源版。
2. 它是否主要解决多人、组织、集中治理或规模化部署问题？是则进入企业版规划。
3. 它是否同时具有通用核心与企业管理部分？拆分稳定的公开接口，将通用能力留在开源版，企业实现保持独立。
4. 它是否会让 AI 获得秘密原文或绕过用户授权？无论哪个版本都不接受。

## 发布与验收边界

开源版公开发行仍需完成跨平台自动化、真实连接器服务、安装生命周期、已知秘密泄漏检查、许可证、SBOM、校验值和文档一致性检查。真实桌面人工验收压缩为每个正式支持平台一次完整冒烟流程，不建设企业审计或认证证据产品。

企业版未来另行定义身份隔离、权限矩阵、集中审计、规模性能、灾备、签名分发、商业支持和客户验收标准。企业版标准不得反向成为开源版发布的隐性阻塞项。
