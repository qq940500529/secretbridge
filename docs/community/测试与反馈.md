# Beta 测试与反馈

[项目首页](../../README.zh-CN.md) / [文档中心](../README.md) / Beta 测试与反馈

SecretBridge 的自动化检查覆盖三平台构建、浏览器流程、真实数据库夹具、安装包生命周期、依赖许可与漏洞门槛。不同硬件、桌面会话、系统凭据库和浏览器配置仍需要用户在真实环境中验证。Beta 测试的目标是获得可复现证据，不是让用户承担开发或排障工作。

## 最短测试流程

1. 从[最新 Beta Release](https://github.com/qq940500529/secretbridge/releases/tag/v0.2.0-beta.9)下载匹配平台的包，核对 SHA-256 和包内清单。
2. 按[安装与后台运行](../getting-started/安装与服务管理.md)完成安装和首次启动，阅读并同意双语[许可协议与免责协议](../最终用户许可与免责声明.md)。
3. 只创建一次性合成凭据，验证写入、覆盖、删除和删除后不可用。
4. 建立合成任务，分别验证批准、拒绝、超时、取消、输出脱敏和审计记录。
5. 停止并启动服务；条件允许时注销或重启，检查配对、非敏感配置和后台恢复。
6. 完成升级、受支持的回滚和卸载，记录用户数据保留选择及残留检查。

不得为通过测试而关闭 TLS、SSH 主机验证、凭据库保护、防火墙或其他安全机制。不要连接未获授权的系统，也不要把真实密码、令牌、私钥或业务数据用作测试材料。

## 怎样提交有效反馈

普通缺陷使用 [Beta 问题表单](https://github.com/qq940500529/secretbridge/issues/new?template=bug_report.md)。请提供：

- SecretBridge 包版本和来源；
- 操作系统版本、架构、安装方式及相关浏览器版本；
- 使用合成数据的最短复现步骤、期望结果和实际结果；
- 是否能在重启后复现，以及卸载和清理是否完成；
- 已脱敏的错误文本；截图必须遮盖私人地址、主机名、用户路径和业务内容。

可能导致凭据、隐私、安全边界或数据完整性受损的问题，请勿公开，改用 [GitHub 私密安全报告](https://github.com/qq940500529/secretbridge/security/advisories/new)。功能建议使用[建议表单](https://github.com/qq940500529/secretbridge/issues/new?template=feature_request.md)。

维护者会确认问题是否可复现、标注受影响版本，并把修复放入正常 PR 和自动化检查流程。公开反馈不构成付费支持或确定的修复时限。
