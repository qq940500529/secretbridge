# SecretBridge 安全模型与验收

[项目首页](../README.zh-CN.md) / [文档中心](README.md) / 安全模型

SecretBridge 的安全目标是限制正常产品接口：AI 可以请求本机代理使用凭据完成任务，但不能通过 Web、MCP 或导出功能读取凭据原文。安全控制服务于功能，不建设单独的认证、试点或证据管理产品。

## 保护对象

- 密码、API令牌、SSH私钥、Cookie和短期认证材料；
- 已解析的命令参数、环境变量、临时文件和协议认证字段；
- 可能回显秘密的 stdout、stderr、错误、日志和历史；
- 用户对连接、任务、有效期和执行次数的授权决定。

## 信任边界

| 主体 | 默认信任 | 能力边界 |
|---|---|---|
| 本机用户 | 可信 | 录入/清除秘密、配置任务、作出授权决定 |
| Web 控制台 | 配对后可信 | 管理配置和任务；仍没有秘密回读接口 |
| 后台代理 | 可信执行面 | 可在运行期间从系统凭据库取密并代用 |
| AI/MCP 客户端 | 不信任其保密能力 | 凭据操作只返回受限结果；普通终端不注入凭据且输出不作通用脱敏承诺 |
| 普通终端 | 用户代码执行面 | 可执行普通命令，但不自动取得 SecretBridge 凭据 |
| 目标服务 | 仅信任必要协议行为 | 可能失败或回显认证信息，输出必须经过筛选 |

## 必须随功能保留的控制

1. 不提供读取、导出或枚举秘密原文的 API/MCP 工具。
2. 密码、令牌和密钥放入操作系统凭据库，SQLite只保存引用和状态。
3. Web 默认只监听本机；写操作需要有效会话和精确 Origin。
4. 普通终端和凭据任务使用不同执行路径，秘密不进入持久 Shell。
5. 凭据任务只按已保存模板注入，AI 请求中不包含秘密值。
6. 输出在返回、记录或持久化之前进行跨分片脱敏。
7. 模板/连接变化使旧授权失效；运行支持幂等、超时、取消和明确终态。
8. 临时环境、临时文件和内存缓冲在完成、失败、取消和启动恢复时清理。
9. TLS、SSH 主机密钥等目标身份验证默认启用，不静默降级。
10. 日志、审计和诊断包只记录必要元数据和脱敏结果。

## 注入风险

SecretBridge 已支持固定程序任务的四种注入方式，UI 明确说明差异：

- 原生协议或标准输入通常优先；
- 环境变量可能被同用户进程读取，只作用于目标子进程；
- 命令参数可能出现在进程列表中，必须显式选择且不能写入历史；
- 临时文件必须使用私有目录、最小权限，并在异常恢复时删除；
- 任何方式都必须经过同一输出脱敏和审计边界。

不因为某种方式不完美就阻止所有功能，也不把风险提示写成“绝对安全”承诺。

## 明确不保证的范围

如果 AI 或其他程序已经拥有凭据所有者同一操作系统账号下的任意代码执行权限，它可能直接调用系统凭据库、读取进程内存、调试代理或绕过 SecretBridge。这超出单机同用户应用能够完全解决的范围。

当前产品承诺的是：秘密没有读取或导出接口，代理只在用户配置和授权的任务中代用凭据；命令输出在保存和返回前过滤已绑定秘密的原文及明确支持的编码形式。过滤不是万能的秘密识别，不保证 Base64、加密、自定义变换、未绑定敏感数据或恶意程序主动外传；详见[凭据命令任务](凭据命令任务.md)。未来可通过专用服务身份和操作系统权限进一步增强，但它不是核心功能开发的前置阻断项。

## 功能开发期间的验收

每个凭据功能至少覆盖：

- 未配对、错误 Origin、过期会话和越权请求被拒绝；
- 设置秘密后响应不含原文，SQLite和普通日志不含原文；
- AI 工具 schema 没有秘密字段或读取接口；
- 模板版本、授权有效期、幂等和取消行为正确；
- stdout/stderr 在任意位置分片时不会直接回显已知秘密；
- 执行失败、超时、取消和服务中断会清理临时材料；
- 连接器只返回约定字段或稳定错误代码。

测试使用合成秘密。真实服务测试使用临时、最低权限账号，测试值不提交到仓库。

## 发布前集中验收

核心功能达到 Beta 后集中完成：

- Windows、Linux、macOS 凭据库与安装目录权限；
- IPC、会话重放、审批绕过和同用户限制说明；
- 编码、分片、输出洪泛、崩溃恢复和长时间运行；
- 依赖漏洞、许可证、SBOM、构建复现和签名；
- 安装、升级、回滚、卸载和诊断包检查。

这些内容以开发测试、CI和发布清单维护，不重新建立面向普通用户的证据中心。

## 泄露事件处理

发现可能泄露时：停止相关新任务，撤销或轮换源系统凭据，保存不含秘密的最小诊断信息，确认可能执行的远端操作，修复输出或注入链后使用合成秘密复测。未经用户明确要求，不重写 Git 历史或删除业务系统记录。
