# Telnet 凭据任务

[文档中心](README.md) / Telnet 凭据任务

> Telnet 会以明文传输账号、密码、命令和输出，也不能验证服务器身份。只应把它用于无法升级、位于可信隔离网络的旧设备。能够使用 SSH 或 TLS 时，不要使用 Telnet。

## 何时可以启用

Telnet 默认关闭。一次任务必须同时满足以下条件：

1. 连接类型为“Telnet 旧设备”，并逐连接开启“允许不加密协议”。
2. 模板中的主机、账号和密码凭据与连接目录完全一致。
3. 用户在审批页看到明文风险、固定地址、登录提示符和完整命令脚本后批准。

关闭连接的明文许可、修改连接或修改模板都会使旧审批失效。SecretBridge 不会为了连接成功而关闭 SSH/TLS 校验，也不会把 Telnet 描述为安全或加密连接。

## 配置

| 字段 | 作用 | 限制 |
|---|---|---|
| 主机与端口 | 唯一允许连接的目标 | 固定值；不能由运行参数替换 |
| 登录账号 | 登录阶段发送的账号 | 固定值；必须与连接目录一致 |
| 密码凭据 | 协议认证 | 仅使用 `protocol` 插槽；不进入命令行或配置数据库 |
| 账号、密码、命令提示符 | 识别设备登录对话 | 每项最多 128 个 ASCII 可见字符 |
| 认证失败提示 | 提前识别拒绝 | 可选，例如 `Login incorrect` |
| 固定命令脚本 | 登录后逐行执行 | 1–32 行；每行最多 2 KiB；禁止换行和控制字符 |
| 退出命令 | 脚本结束后关闭会话 | 固定单行命令 |
| 输出上限 | 限制设备返回内容 | 1 KiB–256 KiB；超限立即关闭连接 |

任务还受模板的 1–300 秒总超时约束。取消、超时、认证失败、断线或输出超限都会丢弃协议连接；不会继续在后台持有 Telnet 会话。

## 执行与结果

代理直接建立 TCP/Telnet 会话，拒绝服务端提出的可选 Telnet 功能协商，只保留基本行式登录。流程固定为：

1. 等待账号提示符，发送固定账号；
2. 等待密码提示符，从系统凭据库取出密码并发送；
3. 等待命令提示符或认证失败提示；
4. 逐行发送固定脚本，每行都必须重新出现命令提示符；
5. 发送退出命令并关闭连接。

设备可能回显密码。SecretBridge 在连接前把密码加入跨分片脱敏器，输出先脱敏再进入 SQLite、Web 或 MCP。Telnet 没有通用的远程退出码：任务成功表示登录对话和固定脚本完整走完，不表示设备一定完成了业务变更。应让只读命令返回可核对的状态文本，并在审批页限制命令范围。

公开错误只使用固定代码，例如 `connection_failed`、`authentication_failed`、`connection_closed`、`output_limit_exceeded`、`timed_out` 或 `cancelled`；底层网络异常和凭据值不会返回给页面或 MCP。

## 迁移建议

- 优先启用设备自带的 SSH、HTTPS 或厂商安全管理协议。
- 无法升级时，把设备放入受限管理网段，只允许必要的管理主机访问。
- 使用独立、最小权限账号，不与其他系统复用密码。
- Telnet 仅用于短期兼容；迁移完成后关闭连接的明文许可并删除相关模板。
