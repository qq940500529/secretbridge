# 自动化安全验收

[项目首页](../README.zh-CN.md) / [文档中心](README.md) / 自动化安全验收

本验收面向开源版正常产品接口，使用一次性合成凭据检查秘密是否越过预期边界。测试不会读取用户已有凭据，也不把通过结果描述成恶意同用户进程隔离、渗透测试或第三方安全认证。

## 合成凭据矩阵

每个测试创建独立的凭据引用、连接、任务、授权和运行，并用唯一 canary 替换内存凭据库中的测试值。

| 维度 | 自动化覆盖 |
|---|---|
| 固定程序注入 | 标准输入、子进程环境变量、参数、短期文件 |
| 流式返回 | stdout、stderr、逐字符输出、跨分片脱敏 |
| 产品接口 | 凭据引用、连接、模板、授权、运行、事件和运行输出 API |
| 维护产物 | 非秘密配置导出、精简诊断、SQLite 一致性备份 |
| 生命周期 | 成功、主动取消、超时和启动残留清理 |
| 编码形式 | UTF-8、UTF-16 大小端、JSON 转义、URL 百分号大小写形式 |

扫描断言只报告发生泄漏的表面名称，不在失败消息中打印 canary。子进程环境变量测试同时确认代理父进程环境没有被修改。短期文件测试会先确认文件确实在执行期间创建，再验证成功、取消或超时后目录为空。

HTTP、SSH、SFTP、Git、PostgreSQL 和 MySQL 继续由各连接器的真实服务测试覆盖协议认证、错误映射和输出过滤；集中矩阵用于防止公共持久化与返回接口发生跨连接器回归。

## 执行命令

完整 Rust 工作区测试会自动包含 canary 矩阵：

```sh
cargo test --workspace --all-targets
```

只运行集中验收：

```sh
cargo test -p secretbridge-server security_acceptance -- --nocapture
```

Windows 和 macOS 上可以显式验证 Credential Manager 或 Apple Keychain。该测试创建随机 ID 的一次性条目，覆盖写入、读取、覆盖、删除、删除后失败与模拟失败清理；它被标记为忽略，避免在没有桌面凭据服务的环境中隐式运行：

```sh
cargo test -p secretbridge-server native_store_round_trip_uses_a_disposable_entry -- --ignored --nocapture
```

仓库的 Windows 和 macOS CI 会执行上述实机凭据库测试。Linux Secret Service 的锁定／无 D-Bus 情况和 macOS Keychain 的锁定或授权提示仍需对应桌面环境人工确认，跟踪于 [Issue #38](https://github.com/qq940500529/secretbridge/issues/38)。

## 通过条件

- 所有受支持编码形式均未出现在扫描表面；
- 正常输出包含 `[REDACTED]`，证明测试确实经过输出过滤器；
- 父进程环境没有因子进程凭据注入而改变；
- 成功、取消和超时后不保留受管凭据临时文件；
- Windows 一次性原生凭据条目能够写入、读取并完成删除；
- 测试只使用合成数据，不依赖业务账号、私有地址或生产服务。

## 明确边界

SecretBridge 限制 Web、MCP、维护接口和受控执行器的正常行为。测试不承诺识别程序对秘密实施的任意变换，也不隔离已经取得当前操作系统账号任意代码执行权限的恶意软件。命令参数和子进程环境变量仍可能被同用户系统工具观察，因此产品优先推荐标准输入或原生协议认证，并在界面中展示注入风险。
