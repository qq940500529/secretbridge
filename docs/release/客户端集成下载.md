# 客户端集成下载 / Client integration downloads

SecretBridge 的每个新 Release 同时提供完整软件包和独立客户端附件。它们使用同一个版本与源码提交，完整软件包仍包含集成文件。已有适用版本的本机代理时，不必为了取得 Skill 或插件重新下载三平台软件包。

Each new Release provides native software packages and separate client downloads built from the same version and commit. Native packages still include the integrations. A client download is not the broker and does not install or initialize it.

## 选择下载 / Choose a download

| 附件后缀 / Suffix | 内容与使用方式 / Contents and use |
|---|---|
| `codex-plugin.zip` | Codex 预构建插件、MCP 配置、操作 Skill 与图标；解压后按客户端的本地插件安装流程使用 / Prebuilt Codex plugin, MCP configuration, Skill and icon |
| `workbuddy-connector.zip` | WorkBuddy 连接器定义、图标、MCP 配置与专用 Skill / WorkBuddy connector definition, icon, MCP configuration and dedicated Skill |
| `workbuddy-skill.zip` | 单独的 WorkBuddy Skill，`SKILL.md` 位于 ZIP 根目录，便于从客户端导入 / Dedicated WorkBuddy Skill with `SKILL.md` at the ZIP root |
| `deepseek-harness.tgz` | 原生 npm bundle，直接可运行的 JavaScript，无安装期构建脚本 / Native npm bundle with prebuilt JavaScript and no installation build scripts |
| `operations-skill.zip` | 完整通用操作 Skill 目录，含 `references/`；用于支持 Agent Skills 的其他客户端 / Complete generic operations Skill, including references |

文件名形式为 `secretbridge-VERSION-后缀`。所有附件均附带同名 `.sha256`。包内 `INTEGRATION.json` 记录匹配的代理版本、API、不可变源码提交和各文件摘要，并包含许可、版权及本页说明。它们是跨平台集成文件，不包含另一个代理程序，也不包含任何用户的路径或秘密。

Names follow `secretbridge-VERSION-SUFFIX`. Check the matching `.sha256` before opening. Each archive contains an `INTEGRATION.json` inventory, matching broker/API version, immutable source reference, license and copyright. These portable client files contain no broker executable, user-specific paths or secrets.

## 先配置本机启动入口 / Configure the local launcher first

独立插件中的默认 MCP 命令为 `secretbridge --mcp-stdio`，需要客户端能够在自己的进程环境中找到该命令。**安装 SecretBridge 不等于已把它加入 PATH。**通过 Finder、开始菜单等启动的客户端也可能使用不同的 PATH。若使用自定义数据目录，还须让桥接使用与代理一致的 `SECRETBRIDGE_DATA_DIR`。

Portable MCP templates use `secretbridge --mcp-stdio`. The client must resolve that command in its own environment; installing the broker does not imply adding it to PATH. Desktop applications may have a different PATH. Custom data directories require the same `SECRETBRIDGE_DATA_DIR` in both broker and bridge.

推荐先用已安装代理的绝对路径导出个性化配置，不需要编译、读取凭据或下载其他运行时：

```text
secretbridge client-plugin codex <absolute-new-directory>
secretbridge client-connector workbuddy <absolute-new-directory>
secretbridge client-plugin deepseek-harness <absolute-new-directory>
secretbridge client-config generic
```

Use the installed binary's absolute path when it is not on PATH. These commands export personalized prebuilt integrations or print configuration without reading credentials. Destinations must not exist; they are not silently overwritten. The native exporter uses the stable installed launcher, including the correct data directory.

若直接使用下载的配置模板，请先用 `client-config` 的输出替换其中的 MCP 启动配置，再按客户端规则导入。不能把安装路径、账号目录、令牌或凭据写回公开下载包或提交到仓库。Codex 插件与普通 MCP 配置只选一种，不要重复注册同一个服务。WorkBuddy 连接器下载不代表已通过其官方市场审核；Skill 可以单独导入，但不能替代 MCP 连接。

For direct template use, replace the MCP launch configuration with the installed binary's `client-config` output before importing. Do not publish personalized copies or register the same MCP server twice. Downloading a WorkBuddy connector is not official marketplace approval. A Skill alone does not connect MCP.

Harness 支持安装下载的预构建 tarball：

```text
dsh plugin --profile <profile> add <downloaded-deepseek-harness.tgz>
dsh --profile <profile> --dump-config
```

This requires a compatible Harness 0.2.x runtime (`>=0.2.0-rc.1 <0.3.0-0`) and a correctly configured MCP launcher. For a custom launcher, install the personalized directory exported above instead. No npm publication or registry account is required to use this release attachment.

## 验证连接 / Verify connectivity

先确认本机代理已由用户完成协议、PIN 与恢复密钥初始化，再从客户端调用只读工具 `secretbridge_terminal_capabilities`；Harness 中名称为 `mcp__secretbridge__secretbridge_terminal_capabilities`。然后通过 `secretbridge_list_catalog` 核对语言与资源元数据。接入成功不授予业务操作权限，也不允许读取秘密。

Initialize the broker locally, then call the read-only capabilities tool. Harness prefixes its name as shown above. Read the catalog for language and metadata. Successful integration grants no operation approval and exposes no secret values.

源码对应版本和逐平台人工验证边界以同一 Release 的说明为准。Skill、插件和代理版本应匹配；更新时使用完整的新目录，不混用不同版本的文件。

Use the corresponding Release for source and validation limits. Keep broker and integration versions matched, and replace complete client directories rather than mixing files from different releases.

## 维护发行附件 / Maintainer release procedure

`Native packages` 工作流从同一标签生成三平台软件包和 `secretbridge-client-integrations` 构建产物。客户端任务会测试包结构、两次独立打包的字节一致性、文件清单及摘要。发布时，将该产物中的五个归档及五个 `.sha256` 与三平台软件包及其校验文件一起上传到同一个 Release；不要发布 CI 元信息、个性化导出目录或临时配置。

The `Native packages` workflow builds all platforms and the `secretbridge-client-integrations` artifact from one tag. Its client job tests archive layout, two independent packaging runs, inventories and digests. Attach all five client archives and five sidecars to the same Release as the native archives and checksums. CI metadata and personalized exports are not public release assets.

维护者也可从干净的对应标签检出执行 `python tools/release/package_client_integrations.py --output <empty-directory>`，再用 `--verify <directory>` 校验。命令不执行客户端安装、仓库发布或凭据操作；发布须按项目的人工批准流程完成。

Maintainers can also build from a clean tag checkout using `python tools/release/package_client_integrations.py --output <empty-directory>` and validate with `--verify <directory>`. Packaging performs no client installation, registry publication or credential operations. Follow the project's human-approved release process.
