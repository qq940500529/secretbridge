## 开源贡献与商业再许可是两件事

贡献者须有权按 `AGPL-3.0-or-later` 或经记录的兼容第三方条款提交内容。贡献者保留实际拥有的版权；提交或合并PR不构成版权转让，也不自动授予数链创元（天津）信息技术有限责任公司专有再许可权。

[DCO 1.1](https://developercertificate.org/)确认的是贡献来源与提交资格，并不是一份版权转让或闭源商业再许可协议。不得只凭Signed-off-by行把外部代码纳入商业授权。

<a name="section-2"></a>

## 商业版本的权利门槛

| 来源 | 商业发行前需要 | 未满足时 |
| :--- | :--- | :--- |
| 公司职务或委托成果 | 核实并留存公司享有权利的合同或其他证明 | 暂不纳入商业许可范围 |
| 外部原创贡献 | 实际权利人明确授予必要商业再许可权的独立书面协议 | 保留开源贡献；商业版排除或重新取得授权 |
| 第三方宽松许可代码 | 核对对应版本许可、版权与NOTICE等条件 | 未核验不引入商业产物 |
| 第三方Copyleft代码 | 核验组合方式与义务是否与商业交付相容 | 替换、隔离、履约或取得原权利人另行许可 |

采用独立、非独占的贡献授权时，应明确公司可复制、修改、分发以及在开源或专有条款下再许可的范围；如涉及专利需单列。贡献者继续保有版权。具体协议须经法律审核，并由真正的权利人或有权代表确认。

<a name="section-3"></a>

## 维护流程

1. PR记录引入内容的来源、许可证、作者与雇主／委托方权利关系是否已确认。
2. 开源合入审查与商业再许可审查分开记录，不以其中一个替代另一个。
3. 建立受限权利台账，关联提交哈希、授权范围、协议编号、权利主体、审查人及日期。
4. 商业发行清单逐项对照台账；权利缺失的代码及其衍生部分必须剔除，不能只删除版权头。
5. 对需要对外提供的源码与通知建立公开交付清单；合同、签名及身份材料留在受限记录中。

未签署的草案、聊天意向、仓库署名或公司版权声明本身，均不能补齐既有第三方版权链。政策对未来贡献生效，不追溯构成他人同意。

## 参考依据
