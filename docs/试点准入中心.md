# 安全试点准入中心

[文档中心](README.md) / [完整路线图](../ROADMAP.md) / [安全验证中心](安全验证中心.md)

安全试点准入中心从 `0.1.0-alpha.17` 开始提供。它把“本机技术配置是否完整”和“是否已取得外部授权与独立证据”放到同一份可校验快照中，避免把成功运行一次连接检查误认为已经获准进入真实试点。

## 它解决什么问题

进入真实低权限试点之前，需要同时回答：

- 是否存在专用测试数据库目标，而不是生产目标；
- PostgreSQL 配置是否完整且强制证书/主机名校验；
- 目标是否关联已配置的系统凭据；
- 是否存在启用的固定、只返回状态的连接检查模板；
- 最近安全自检是否存在、摘要是否完整、是否有失败项；
- 最近平台身份与IPC证据是否存在且摘要完整；
- 安装后身份隔离、目标方授权、远端最小权限和独立安全评审是否有外部证据。

前六类可以由本机程序核对；最后四类不能由产品自己替负责人或评审者作证。因此即使技术链全部完整，当前快照也只会显示“待人工门槛”，不会自动声称“可进入试点”。

## 检查项

| 代码 | 类别 | 自动判断 | 通过含义 |
|---|---|---|---|
| `test_target_available` | 配置 | 是 | 至少一个 database/test 目标 |
| `postgres_configuration_complete` | 配置 | 是 | 至少一个测试目标具备完整 `verify_full` 配置 |
| `credential_available` | 配置 | 是 | 至少一个测试目标关联状态为 available 的凭据引用 |
| `controlled_template_available` | 配置 | 是 | 至少一个目标具备启用的 status-only 固定 PostgreSQL 检查 |
| `latest_validation_digest` | 证据 | 是 | 最近安全验证的摘要重新计算一致 |
| `latest_validation_result` | 证据 | 是 | 最近安全验证没有失败；warning 原样传递 |
| `latest_platform_evidence_digest` | 证据 | 是 | 最近平台身份与IPC证据的摘要重新计算一致 |
| `identity_boundary_evidence` | 人工门槛 | 否 | 三平台安装身份与 IPC 边界有独立证据 |
| `pilot_authorization_record` | 人工门槛 | 否 | 目标负责人批准限时非生产试点 |
| `least_privilege_review` | 人工门槛 | 否 | 独立人员确认远端账号权限集合 |
| `independent_security_review` | 人工门槛 | 否 | 安全敏感实现已由非原实现人员复核 |

状态计算规则固定：任一 `failed` 产生 `blocked`；没有失败但存在 `warning` 产生 `attention`；只有全部通过才可能为 `ready`。当前 profile `pilot-readiness-v1` 保留四个人工警告，因此不会自行产生 `ready`。

## 使用流程

1. 在“安全验证”页面运行完整自检；
2. 在“平台证据”页面采集当前身份与IPC事实；
3. 配置专用测试目标、系统凭据和固定 PostgreSQL 检查模板；
4. 打开“试点准入”，点击“生成完整准入快照”；
5. 逐项处理技术阻断；
6. 下载 Markdown 或 JSON，交由目标负责人和独立评审者补充外部证据；
7. 在未来的获批试点版本中引用这些证据，而不是在当前系统里自行勾选通过。

## API

| 方法与路径 | 行为 | 边界 |
|---|---|---|
| `GET /api/v1/pilot-readiness` | 返回最近到最早的快照 | 需要页面会话；只含非秘密固定证据 |
| `POST /api/v1/pilot-readiness` | 对当前完整目录生成一份快照 | 需要页面会话和精确 Origin；请求体必须为空 |
| `GET /api/v1/pilot-readiness/{id}` | 读取单份快照并重算摘要 | 找不到返回 404 |
| `GET /api/v1/pilot-readiness/{id}/report` | 返回快照、摘要校验、Markdown 和范围声明 | 不返回目标名称、地址、用户名、凭据或审批备注 |

创建接口不接受目标 ID、跳过项或调用方结论，防止调用方只选择容易通过的目标或删除人工门槛。所有测试目标按固定 SQL 聚合，只在报告中输出数量。

## 持久化与完整性

SQLite schema v9增加准入表；当前schema v10同时保存平台边界证据：

- `pilot_readiness_snapshots`：版本、状态、应用/平台、时间、最近验证 ID、候选数、技术就绪数和 SHA-256；
- `pilot_readiness_checks`：最多 64 个有序固定检查；
- 历史总量上限 128 份，达到容量时明确拒绝，不静默覆盖旧证据。

摘要覆盖快照 ID、profile、状态、应用、平台、时间、最近验证 ID、计数和有序检查。读取详情或报告时重新计算；不一致时 `digest_verified=false`。SHA-256 用于发现记录变化，不提供作者身份或不可抵赖性，也不是发行签名。

## 数据边界

准入中心不会：

- 读取操作系统凭据值；
- 连接任何 PostgreSQL 或业务系统；
- 输出目标名称、主机、端口、库名、用户名或凭据引用；
- 替目标负责人授权；
- 探测远端账号真实 grants；
- 把本机产品自检称为独立安全认证；
- 改变 `unverified_same_user` 公开身份状态。

## 验收基线

- 空目录生成 11 项快照且状态为 `blocked`；
- 建立完整测试目标、可用凭据、固定模板和最近自检后，没有技术失败，整体仍为 `attention`；
- 修改任一持久化检查证据后，读取时能发现摘要不匹配；
- v8数据库升级到v9后保留安全验证历史；v9升级到v10后保留准入快照，并可纳入平台证据；
- 未认证、错误 Origin 和非空创建请求分别被拒绝；
- Markdown/JSON 报告包含范围声明，不包含密码、目标地址或业务数据；
- Web 客户端、类型检查、生产构建、Rust 测试、Clippy、许可证和三平台 CI 通过。
